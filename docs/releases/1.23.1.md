## Date-format decisions

Daily, monthly and yearly notes each have a list of recognized formats and exactly one **Creation default**. Supported date tokens are `YYYY`, `MM` and `DD`; square brackets protect literal text. Format fields exclude folders and `.md`.

| Note type | Format example | Result example |
| --- | --- | --- |
| Daily | `YYYY-[M]MM-DD` | `2026-M10-13.md` |
| Monthly | `YYYY-[M]MM` | `2026-M10.md` |
| Yearly | `YYYY-[Year]` | `2026-Year.md` |

Changing the creation default keeps existing filenames intact. Moving and copying recognized notes preserves their detected format. Internal dates, reminder calculations and `date_start` / `date_end` remain Gregorian ISO dates. Invalid dates and ambiguous filename interpretations are rejected, including different token structures that happen to yield the same date. Collision suffixes are checked after the final filename is formed.

Daily representative-note lookup checks recognized exact basenames in the selected folder. Monthly and yearly lookup checks the resolved plan path's parent folder. Existing recognized representatives are reused; multiple candidates require a choice. This lookup is separate from **Planner note scan scope**, which controls planner chip discovery and the preview for linking existing colors.

A nonempty **Monthly plan note path** or **Yearly plan note path** takes priority over its creation default. For example, `Periodic/Monthly/YYYY-[M]MM.md` creates `Periodic/Monthly/2026-M10.md`. Existing full-path templates retain their legacy interpretation until edited; new or edited templates support bracket literals. On migration, the former daily date-format setting becomes an additional recognizer when valid, while daily creation initially remains `YYYY-MM-DD`.

## Color decisions

Notes can use **Theme color**, an independent **Fixed color**, or a named linked palette entry. Linked notes store `diary_color_id` and a fallback `color` snapshot. Palette edits update their rendered colors without rewriting every linked file. A fixed color remains independent even when it equals the current theme color. Legacy `color` lists use their first entry.

**Link existing colors** previews eligible unlinked planner notes within the configured scan scope. Nothing is selected initially; changes apply only to selected notes, and partial failures are reported. **Manage linked notes** can reassign links or disconnect selected notes while keeping their current effective color. Archived palette entries disappear from new choices while retaining existing references and their color; they can be restored.

Recurring occurrences can inherit their source color or use an override. Inheritance survives source renames through the stable `recurrence_id`; detachment snapshots the current effective color. **Holiday color** supports theme, fixed and palette choices across the five main planner views and three sidebar variants. Borders, dots and tinted backgrounds follow the selected color while text remains theme-readable.

## Verification and limits

Release verification used **Node.js 24.19.0** locally and **Obsidian 1.14.4**. The exact release checkout passed `npm ci`, `npm run lint`, `npm run build`, `npm test`, `npm run design:lint`, `npm audit --omit=dev`, and `git diff --check`. The regression suites cover date formats, linked colors and all **444 message keys** across **eight locales**.

The [Node.js build workflow](https://github.com/POBSIZ/obsidian-diary/actions/runs/38415998806) passed on Node.js **20.x** and **22.x**. The [release workflow](https://github.com/POBSIZ/obsidian-diary/actions/runs/38416016549) published the three assets. Downloaded release assets matched the installed plugin files, and the running Obsidian plugin reported **1.23.1**.

Runtime checks covered mixed filename formats, creation defaults, representative-note reuse, linked and fixed colors, archived palette entries, fixed colors equal to the theme, selective linking, recurrence source renames, detached color snapshots, legacy color lists, all eight planner view types, and sidebar note routing. Temporary test notes were removed, desktop mode and the original planner layout were restored, and task-created branches and worktrees were removed after integration into `main`.

Mobile UI was checked with WebKit emulation at **834 × 1194** and **360 × 780**, including wrapping controls, 44 px touch targets and light/dark holiday readability. Physical iPad verification was unavailable. The full dependency audit had **12 reviewed development-only advisories**; the runtime dependency audit had **zero vulnerabilities**. Community recommendations about attestations, vault enumeration and clipboard access were nonblocking.
