# Diary 1.26.0 release closeout

Diary [1.26.0](https://github.com/POBSIZ/obsidian-diary/releases/tag/1.26.0) adds a display time zone for external calendars and fixes timed events appearing on the previous UTC date. Implementation, installation and Community distribution were verified on **2026-11-09, Asia/Seoul**. GitHub records publication as **2026-11-08 19:50:53 UTC**, equivalent to **2026-11-09 04:50:53 KST**.

## Problem and shipped behavior

External event times were formatted in the device's local zone, while date grouping used the first ten characters of the UTC timestamp. An event starting at `2026-11-10T23:40:00.000Z` therefore appeared on November 10 even when its displayed local time was November 11 at 08:40 in Asia/Seoul.

**Settings → Diary → External calendar time zone** now defaults to **Device time zone**. Users can select a fixed supported IANA zone, including UTC. Missing or invalid saved values fall back to the device setting. The literal `device` preference follows each device's own zone when settings sync; it does not save a fixed UTC+9 offset.

Date grouping, visible-range filtering, details, external-event note filenames and daily/3-day timeline placement share the selected display zone. Named zones follow daylight saving rules. All-day dates and floating times retain their original values. Existing Planner notes retain their authored wall-clock dates and times. Display conversion operates on event copies; cached timestamps, source instance IDs, recurrence exceptions and linked-overlay identities remain in their source basis.

The settings UI and READMEs describe the same behavior in all eight supported languages. The shared implementation is in [external-calendar-timezone.ts](../../src/utils/external-calendar-timezone.ts) and [external-calendars.ts](../../src/utils/external-calendars.ts).

## Community distribution and browser recovery

Initial browser control returned CDP command and native accessibility timeouts while the browser inventory still responded. A separate unauthenticated HTTP read returned 403; that response was not treated as proof that the signed-in session had failed. GitHub publication and local installation were complete while Community verification remained open.

At the user's explicit request, Chrome's session files were backed up locally and Chrome was restarted. The normal quit request returned without ending the original process; a scoped TERM ended it, and Chrome was reopened with session restoration. Existing tabs and the authenticated Community session were observed after restart. This recovered control; the original cause of the unresponsive process was not established. Session backups remain local and are not part of the repository.

The owner console then confirmed that the manifest pointed to **1.26.0** and queued its scan. The review for **0d72b15** progressed from **Pending** through partial checks to **Completed**. The owner console's **Current release** became **1.26.0**.

The [public listing](https://community.obsidian.md/plugins/diary) was checked in Chrome after completion: **Current version 1.26.0**, an **Updates** entry linking to the 1.26.0 release, **Health Excellent** and **Review Passed**. Dependencies passed with no vulnerable dependencies, and the build reproduced the published `main.js` byte-for-byte.

The Scorecard retained four nonblocking recommendations: two missing asset attestations, vault enumeration and clipboard access. It also disclosed runtime base64 calls and unavailable malware/obfuscation scans. Review Passed does not imply that those unavailable scans ran.

## Remaining maintenance and closeout

There is no open acceptance gate for this release. A full dependency audit reviewed during closeout reported **14 moderate affected development-dependency entries**, rooted in fast-uri, minimatch and the development-only Moment dependency through the tooling/type packages. There were no high or critical entries. Runtime dependency audit and Community dependency review both passed. Tooling dependency remediation remains separate maintenance; this feature did not change dependency versions or apply a force upgrade.

This documentation follow-up retains version **1.26.0** and its original release tag. The root README and development guide link this record. Local agent guidance points external-calendar changes to the shared time-zone helpers and regressions. Existing closeout/release workflows cover the process; no new skill is justified. The pre-existing `.gitignore` edit, runtime settings and local backups remain preserved.
